# Harness adapter v1

워크플로우 실행 엔진은 `dsh-team-chat/workflow-engine`으로 내보냅니다. `dsh-team-chat/harness-adapter`는 인터페이스 버전, 검증 함수, TypeScript의 `HarnessAdapterV1` 타입을 제공합니다.

| 경계 | 계약 |
|---|---|
| 팀과 Agent | `team(teamId)`는 안정적인 팀 ID, 리드 ID, 기존 Agent 세션 ID와 작업 공간을 반환합니다. Agent ID는 한 어댑터 인스턴스 안에서 유일해야 합니다. |
| 턴 | `startTurn`은 요청별 `turnId`, Agent ID, 입력, 도구 정책, `AbortSignal`을 받습니다. 반환한 핸들은 해당 턴의 최종 결과와 대기·승인·질문 상태, 취소 후 정리 완료를 구분합니다. |
| 안전 기능 | 격리된 턴과 요청 범위의 취소를 보장해야 합니다. 이를 제공할 수 없는 어댑터는 거부됩니다. `text-only` 턴에서는 도구를 실행할 수 없어야 합니다. `native-approval`은 별도 권한 지원이 있을 때만 사용할 수 있습니다. |
| 작업 보드 | 선택 기능입니다. 없으면 엔진의 저장된 워크플로우 상태로 진행하며 원본 작업 ID는 생성하지 않습니다. 보드가 있으면 변경에 revision 검사와 안정적인 작업 ID를 적용합니다. |
| 파일 | 선택 기능입니다. 작업 공간 안의 정규 경로 확인, 내용 해시, 읽는 동안 파일 교체 감지가 필요합니다. 폴더 감시는 별도로 지원할 수 있습니다. |
| 저장소와 방 | 엔진 생성 시 저장소의 `get`, `entries`, `put`과 방 어댑터의 `members`, `requestText`, `publish`, `annotate`, `stopping`, `stopConversation`, `logger`를 제공합니다. 호출자 인증과 사용자 승인 UI는 호스트가 맡습니다. |

실행 기록은 어댑터 ID와 인터페이스 버전에 묶습니다. 다른 Harness로 워크플로우 정의를 옮길 때는 새 대상의 Agent ID를 매핑해 새 실행을 시작합니다. 기존 실행, 원본 작업 ID, 체크포인트는 생성한 어댑터에서 복구합니다. 기존 DSH 기록을 읽을 수 있도록 DSH 방 연결만 레거시 출처를 지정합니다.

현재 포함된 실제 연동은 DeepSeek Harness입니다. 별도 가짜 어댑터를 사용한 계약 테스트로 원본 작업 보드가 없는 실행, 도구 기능이 없는 경우의 권한 차단, 다른 어댑터에서 생성한 실행의 재시작 거부를 확인합니다. 다른 Harness의 로그인, 화면 장착, 저장소 및 도구 승인 연동은 해당 어댑터에서 구현해야 합니다.
