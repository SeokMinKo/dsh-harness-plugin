# Team Chat for DeepSeek Harness 0.3.2

기존 Agent Team의 리드와 팀원 세션을 한 대화방에서 사용합니다. 팀을 만들 때 연결한 모델과 각 세션의 컨텍스트가 이어집니다. 호환 대상은 DeepSeek Harness 코어 **0.2.2-rc.1**입니다.

## 설치와 업그레이드

1. `dsh-team-chat-0.3.2.tgz`를 Desktop을 실행하는 컴퓨터에 저장합니다.
2. Desktop **Plugins**에서 **Agent Teams**를 활성화합니다.
3. 설치된 이전 Team Chat 패키지가 있다면 **Plugins**에서 Team Chat 패키지를 제거합니다. 이전 버전으로 되돌릴 계획이 있다면 먼저 DSH 저장소를 백업합니다.
4. **Plugins → Add plugin**에서 새 파일의 절대 경로를 입력하고 **Install → Enable now**를 선택합니다.
5. 기존 팀의 리드 세션을 엽니다. 사이드바의 **Team Chat** 또는 세션 헤더의 말풍선으로 방을 엽니다. 새 방은 참여할 팀원 2~6명을 선택합니다.

Desktop의 **Manage dsh Command**로 등록한 명령을 사용할 때는 Desktop을 완전히 종료한 뒤 `dsh plugin --profile desktop add "/absolute/path/dsh-team-chat-0.3.2.tgz"`를 실행합니다. Desktop과 Web은 플러그인 설치 프로필이 다릅니다. 아래 명령은 Web 프로필을 사용하는 경우입니다.

Web 프로필에서 새로 설치하려면 다음을 실행합니다. 기존 설치를 갱신할 때는 같은 프로필에서 먼저 `dsh plugin --profile web remove dsh-team-chat`를 실행합니다.

```sh
dsh plugin --profile web add "/absolute/path/dsh-team-chat-0.3.2.tgz"
dsh web
```

## 사용법

| 입력 또는 동작 | 결과 |
| --- | --- |
| `@test 이 이미지를 검증해줘` | 기존 test 세션 호출 |
| `@watch @test 확인해줘` 또는 `@all` | 명시한 팀원 또는 방 전체를 순차 호출 |
| 멘션 없는 메시지 | 리드 또는 방의 첫 참가자가 응답 |
| 팀원 말풍선의 **답장** | 해당 팀원에게 답장 |
| **답변하기** | 팀원이 `@user`로 물으면 대기열을 보류하고, 답변을 해당 팀원에게 먼저 전달한 뒤 원래 요청의 남은 팀원 작업부터 계속 |
| **대기열 재개** | 질문을 건너뛰고 원래 요청의 남은 팀원 작업부터 처리 |
| **현재 응답만 중지** | 현재 사용자 요청에서 시작된 응답을 중지하고 다음 대기 요청으로 진행 |
| **방 전체 중지** | 같은 방의 일반 채팅과 워크플로우에서 실행 중이거나 대기 중인 작업을 중지 |
| **원본 세션 열기** | DSH 승인, 질문 또는 원본 세션 대기 상태를 해당 팀원의 세션에서 확인 |
| **기록 검색** | 불러온 메시지의 팀원 이름과 본문 검색 |
| 중단된 메시지의 **다시 작성** | 새 초안으로 불러와 내용을 확인한 뒤 전송 |

팀원은 기본 3라운드, 사용자 요청당 최대 12회까지 서로 후속 발언을 요청할 수 있습니다. **방 설정**에서 라운드 수를 1~3으로 변경합니다. `@`를 입력해 화살표와 Tab으로 팀원을 선택하고, 방을 옮겨도 열린 앱에서 작성 중인 초안을 이어 쓸 수 있습니다.

## 실행 권한과 기록

- 기본은 텍스트 대화입니다. 사용자가 한 팀원을 직접 멘션하거나 그 팀원에게 답장할 때만 메시지별 DSH 도구 사용을 허용할 수 있습니다. 자동 후속 발언은 텍스트로 처리됩니다.
- 승인과 질문은 해당 DSH 원본 세션에서 처리됩니다. Team Chat은 진행 상태와 이동 버튼을 표시합니다. 팀원의 기존 DSH 승인 정책과 모델 설정이 적용됩니다. 출력 토큰 한도에서 잘린 응답은 실패로 기록하고 후속 팀원을 호출하지 않습니다.
- 방의 메시지 기록은 DSH 저장소에 기록됩니다. 이전 버전의 기록은 읽을 수 있고 오래된 확정 메시지부터 64개 단위로 보관됩니다. 저장 형식이 갱신된 뒤 이전 버전으로 돌아가려면 기존 저장소 백업을 사용합니다.
- 사용자에게 답을 기다리는 요청은 남은 팀원 작업과 함께 재시작 후에도 보류됩니다. 호스트가 실행 도중 종료되면 진행 중이던 요청은 중단으로 표시됩니다. 다시 실행하려면 메시지를 검토한 뒤 전송합니다.
- 한 기존 팀에 텍스트 대화방 하나를 연결합니다.

## 소스와 테스트

소스, 단위 테스트, 재현용 저장소 벤치마크가 패키지에 포함됩니다. `npm install`, `npm test`, `npm run build`로 소스를 검사할 수 있습니다. 벤치마크는 `node test/performance.mjs`로 실행합니다.

제품별 비교와 0.2.0의 10회 개선 기록은 [COMPARISON.md](COMPARISON.md)에 있습니다.

## 0.2.3의 재연결 처리

연결을 복구하면서 받은 최신 페이지가 기존 기록과 이어지면 이미 불러온 이전 기록과 검색 결과를 유지합니다.

## 0.2.2에서 확인한 작업 분배 범위

팀원 응답의 마지막 줄에 있는 인계 지시를 해석해 다음 팀원을 호출합니다. 상대가 같은 요청에 이미 포함된 경우에는 한 번만 호출하며, 앞 팀원의 인계 내용을 원래 사용자 지시와 구분해 전달합니다. 여러 팀원 중 일부가 실패하면 원래 요청은 **일부 실패**로 표시됩니다. 이 방의 분배 단위는 대화 발언과 텍스트 인계입니다. DSH Agent Teams의 원본 세션에서는 별도로 공유 작업 보드를 사용할 수 있습니다. [DSH Agent Teams](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.2.2-rc.1/packages/experimental/agent-team/README.md)

## 0.2.2 재점검 결과

- 대화방에 속한 응답이 실행되는 동안 원본 세션에 보낸 독립 입력은 원본의 다음 턴으로 옮깁니다. 같은 세션의 기존 문맥과 해당 턴에서 생성된 도구·시스템 문맥은 계속 사용합니다.
- 모델의 최종 텍스트만 팀원 인계를 결정합니다. 도구를 호출한 응답의 사전 설명, 비어 있는 최종 응답, 출력 한도에서 잘린 응답은 후속 팀원 호출에 쓰이지 않습니다. 모델이 정상 완료한 긴 응답은 마지막 줄의 인계 지시까지 읽고 방에서는 앞뒤를 보존해 표시합니다.
- 한 팀원이 여러 곳에서 인계를 받으면 기존 차례에 모든 인계 출처를 함께 전달합니다. 대상 오류나 라운드 한도로 인계가 막힌 항목은 응답 아래에 표시되고 원래 요청에 **일부 실패**가 표시됩니다.
- 0.2.1 저장 형식과 대기 중인 질문을 읽을 수 있습니다.

## 워크플로우 사용법

1. 기존 팀 방의 **워크플로우**를 엽니다. **채팅으로 설계**에서 Agent 역할과 순서를 설명하거나, 패널에서 시작 형태를 선택한 뒤 노드를 배치합니다.
2. 설계 제안의 변경 목록과 흐름도를 보고 **초안에 반영**을 누릅니다. 흐름도에서 작업을 누르면 담당 Agent를, 화살표 또는 조건을 누르면 연결의 실행 조건을 바꿀 수 있습니다. 새 연결은 선행 작업에서 **연결 추가**를 누른 뒤 다음 작업을 선택합니다. 계층 그룹은 작업에 표시되며 실행 순서는 연결이 결정합니다.
3. **버전 저장** 후 **실행 상태**에서 버전, 필요한 입력 파일 및 대상 장비를 확인하고 실행합니다. 네이티브 도구가 필요한 단계는 소유자가 도구를 허용해야 하며, 기존 DSH 승인 정책이 적용됩니다.
4. 작업 카드를 열면 질문, 원본 DSH 세션, 결과 파일과 SHA-256, 대기 이유를 볼 수 있습니다. **채팅에서 답변**은 해당 실행과 질문 ID에 연결됩니다. 초기 병렬 제한은 팀당 2개입니다.
5. 자동 입력을 사용하려면 **폴더 트리거**에서 DSH 작업 공간 상대 경로, 확장자 및 필요한 경우 장비 ID를 입력합니다. 트리거는 적용할 때의 저장 버전을 사용합니다. 같은 파일 내용과 장비 조합은 자동으로 다시 실행되지 않습니다.

팀마다 하나의 초안을 편집할 수 있고, 저장한 버전은 여러 번 실행할 수 있습니다. 현재 실행에는 아직 시작하지 않은 기존 작업의 변경을 적용할 수 있습니다. 새 노드 추가와 삭제는 새 실행부터 적용합니다. 오래된 DSH 작업 보드 제한에 도달하면 원본 보드를 정리한 뒤 연결을 다시 시도할 수 있습니다.

재시작 시 질문과 확정된 결과가 유지됩니다. 장비 작업의 결과가 불명확하면 같은 장비를 사용하는 다음 단계가 대기합니다. 상태 확인 후 해당 작업에서 실패 확정 또는 재실행을 선택합니다. 재시작 후 도구 사용은 작업별로 다시 허용합니다. 파일 트리거는 설정한 디렉터리 한 곳의 일반 파일을 감시하고, 두 스캔에서 파일이 안정된 뒤 해시를 확인합니다.

## 채팅에서 팀 업무 배분

`@lead 이 로그를 팀원들이 나눠 분석해줘`라고 요청하거나 작성창의 **업무 나누기**를 선택합니다. 리드가 배분안을 만들고 원래 메시지에 작업·담당 Agent·완료 조건·선행 작업을 표시합니다. 담당자를 수정한 뒤 **배분안 전체 승인**으로 실행합니다. 도구가 필요한 작업은 해당 단계에서 사용자가 허용하고, DSH 원본 승인 정책도 적용됩니다.

같은 채팅 카드에 각 Agent의 상태, 결과, 결과 파일 및 원본 세션 링크가 표시됩니다. **이 작업만 중지**는 선택한 워크플로우 작업에 적용합니다. 취소한 작업에 의존하는 후속 작업은 보류되고 독립 작업은 계속됩니다. **방 전체 중지**는 이 방의 진행·대기 작업과 미승인 배분안에 적용됩니다. 중지 후 새 메시지는 새 요청으로 처리됩니다.

중지한 작업의 **복구 선택**에서 입력을 수정하고 **중단 지점부터 재개**, **처음부터 재실행**, **이 작업 취소**를 선택할 수 있습니다. 중단 지점 재개는 Agent가 네이티브 턴 사이에 명시적으로 저장한 체크포인트에서 동작합니다. 호스트는 입력과 작업·선행 결과의 지문, 체크포인트 파일 해시를 검사합니다. 호환되지 않으면 이유를 표시하고 재실행 또는 취소를 기다립니다. 장비 도구가 실행 중이었다면 장비 상태 확인을 요구합니다.

## 동작 안전성 및 다른 Harness 연결

대기 중이던 실행은 Host가 다시 올라왔을 때 사용자의 복구 조치를 기다립니다. 승인된 턴의 도구 권한은 해당 작업에 적용됩니다. 작업을 벗어나는 기본 DSH 위임·예약·원본 작업 변경 도구는 차단합니다. OS 명령과 임의의 외부 도구에 대한 제한은 DSH 정책을 따릅니다. 파일은 작업 공간 내부의 상대 경로만 사용하고 Windows 장치명·대체 데이터 스트림 및 심볼릭 링크 경로를 거절합니다.

실행 엔진과 DSH 연결의 인터페이스는 [HARNESS-ADAPTER.md](HARNESS-ADAPTER.md)에 있습니다.
